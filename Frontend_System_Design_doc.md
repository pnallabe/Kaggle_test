# AI Data Analyst — Frontend System Design

## 1. Overview

This document outlines the system design and development plan for the frontend of the AI Data Analyst platform. The frontend is designed to provide a modern, professional, and enterprise-ready user experience, focusing on intuitive data querying, visualization, and multi-tenant workspace management.

**Platform:** Web application (React + TypeScript)
**Hosting:** Google Cloud Storage + Cloud CDN
**Design System:** Tailwind CSS, shadcn UI components
**State Management:** Redux or Zustand
**Data Visualization:** Plotly.js + Chart.js
**Authentication:** Google Identity Platform (OAuth / SSO)

---

## 2. Key Objectives

* Provide a sleek, modern, and responsive UI suitable for enterprise clients.
* Allow users to upload datasets, query via natural language, and view results.
* Integrate seamlessly with backend APIs hosted on Cloud Run.
* Support multi-tenant workspace architecture with secure role-based access.
* Ensure accessibility and responsive design.

---

## 3. Component Architecture

### 3.1 Main Components

| Component                 | Description                                                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **Dashboard / Workspace** | Displays list of projects, datasets, and recent activity. Users can navigate between workspaces.                              |
| **Query Console**         | Input box for natural language queries; displays job status and results. Supports syntax highlighting and inline suggestions. |
| **Dataset Manager**       | Interface for uploading CSVs, connecting to BigQuery or other connectors, and viewing metadata.                               |
| **Results Viewer**        | Shows tables, charts, and visualizations generated by the backend. Supports multiple tabs per query.                          |
| **Insights Panel**        | Provides AI-generated textual summaries and explanations of query results.                                                    |
| **Notebook / History**    | Tracks user queries and allows replay, comments, and sharing.                                                                 |
| **Settings & Profile**    | Manage account, workspace preferences, and access permissions.                                                                |

### 3.2 Layout & Navigation

* **Navigation Bar:** Persistent top navigation with workspace switcher, notifications, and profile access.
* **Side Panel:** Collapsible panel for datasets, projects, and saved queries.
* **Main Content Area:** Dynamic content for query console, results, visualizations, or insights.
* **Modal Dialogs:** For uploading files, dataset connection configuration, or job details.

### 3.3 Reusable Components

* **Buttons / Inputs / Forms:** Tailwind-based design system.
* **Charts:** Plotly.js reusable chart components (bar, line, scatter, histogram).
* **Data Table:** Sortable, filterable tables with export options (CSV, Excel).
* **Alerts / Notifications:** Toast messages for job completion, errors, or info.
* **Loaders / Skeletons:** For asynchronous API calls.

## 4. Frontend Data Flow

### 4.1 Job Submission Flow

1. User types a query in **Query Console**.
2. Frontend validates input and sends POST `/api/v1/jobs` to backend API with dataset references and options.
3. Backend responds with job ID and status.
4. Frontend polls GET `/api/v1/jobs/{job_id}` until status is `finished`.
5. Results Viewer fetches artifacts (tables/charts) via GET `/api/v1/artifacts/{artifact_id}` and renders them.
6. Insights Panel displays explanations generated by Vertex LLM.

### 4.2 Dataset Upload Flow

1. User uploads a CSV via Dataset Manager.
2. Frontend requests a presigned upload URL from backend.
3. Upload is performed directly to GCS.
4. After upload, backend triggers ingestion pipeline and updates metadata.
5. Dataset Manager refreshes dataset list and metadata display.

### 4.3 Workspace & Multi-Tenant Flow

* Workspace list fetched from backend via GET `/api/v1/projects`.
* Users can switch workspaces, each with its own datasets and query history.
* RBAC enforced via backend API; frontend only shows actions allowed by role.

## 5. State Management

* **Global State:** Redux or Zustand to store workspace info, user profile, datasets, query history.
* **Local State:** Component-level state for forms, temporary inputs, and modals.
* **Caching:** Use browser storage or Redux store for recently fetched datasets, query previews, and artifacts to reduce API calls.

---

## 6. API Integration

* **Authentication:** OAuth token sent in `Authorization: Bearer <token>` header.
* **Endpoints:**

  * `/api/v1/jobs` (POST) — submit query job
  * `/api/v1/jobs/{id}` (GET) — fetch job status and results
  * `/api/v1/artifacts/{id}` (GET) — retrieve chart/table artifacts
  * `/api/v1/projects` (GET) — list user workspaces
  * `/api/v1/datasets` (GET/POST) — list and upload datasets
* **Error Handling:** Standardized error codes (400, 401, 403, 500) with toast notifications and inline messages.

## 7. UI/UX Guidelines

* Responsive layout: desktop, tablet, and mobile breakpoints.
* Modern and professional visual style: clean lines, muted color palettes, and minimalistic design.
* Light and dark themes support.
* Accessibility (a11y) compliance: ARIA labels, keyboard navigation.
* Intuitive query history and reusable job templates.
* Loading states, error messages, and inline validation for smooth UX.
* Modular design for adding future features (voice input, notebooks, dashboards).

---

## 8. Component Library & Styling

* **Tailwind CSS:** For utility-based styling.
* **shadcn UI:** Prebuilt accessible components.
* **Icons:** Lucide-react.
* **Animations:** Framer Motion for smooth interactions and modals.
* **Charts:** Plotly.js + Chart.js integrated via React wrappers.

---

## 9. Testing Strategy

* **Unit Tests:** Jest + React Testing Library for components and utilities.
* **Integration Tests:** Cypress for UI workflows, including job submission, dataset upload, and result rendering.
* **Visual Regression Tests:** Storybook snapshots for key components.
* **Performance Testing:** Lighthouse for load time and responsiveness.

---

## 10. CI/CD & Deployment

* **Build:** Vite/webpack build process.
* **CI:** Cloud Build or GitHub Actions for linting, tests, and build.
* **Deployment:** Upload static assets to GCS bucket + Cloud CDN.
* **Versioning:** Use semantic versioning; maintain staging and production environments.
